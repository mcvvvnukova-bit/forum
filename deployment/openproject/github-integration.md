# Как связать задачи OpenProject с GitHub

Проект [АСТ «Форум»](https://roadmap.astforum.ru/projects/PROJ) использует репозиторий [mcvvvnukova-bit/forum](https://github.com/mcvvvnukova-bit/forum).

## Прикрепить ветку или отдельный коммит

Откройте вкладку **GitHub** в задаче и перейдите в связанный PR. На его странице доступны ветка и все входящие в PR коммиты.

Для прямой ссылки на ветку или отдельный коммит добавьте комментарий к задаче:

- Ветка: `https://github.com/mcvvvnukova-bit/forum/tree/ИМЯ_ВЕТКИ`.
- Коммит: `https://github.com/mcvvvnukova-bit/forum/commit/ПОЛНЫЙ_SHA`.

Дополнительные поля **Ветка GitHub** и **Коммит GitHub** удалены по решению владельца проекта 1 октября 2026 года. Связь задачи с PR создаётся по её коду или ссылке в описании PR. Доступ к приватному репозиторию проверяет GitHub.

## Автоматически связать pull request

Pull request (PR) — запрос на включение изменений из ветки в основную ветку проекта.

1. Откройте вкладку **GitHub** в задаче OpenProject.
2. В меню **Git snippets** скопируйте имя ветки и текст для сообщения коммита.
3. Создайте ветку, внесите изменения и отправьте коммит в GitHub.
4. Создайте PR и вставьте полный адрес задачи в **описание PR**. Например: `https://roadmap.astforum.ru/work_packages/PROJ-N`.
5. Вместо адреса можно указать `OP#PROJ-N`, где `PROJ-N` — идентификатор задачи. `OP#` вводится с заглавными буквами.
6. Откройте вкладку **GitHub** в задаче: там появится PR и его статус. Ветка и коммиты доступны на странице PR.

Пример имени ветки: `codex/PROJ-N-short-description`. Само имя ветки или номер задачи только в сообщении коммита не создают автоматическую связь. Для неё нужна ссылка в описании PR или комментарии к PR.

Для одного PR можно указать несколько задач. К одной задаче можно прикрепить несколько PR.

## Настройки интеграции

- В проекте АСТ «Форум» включён модуль **GitHub**.
- В репозитории используется вебхук на `https://roadmap.astforum.ru/webhooks/github` с типом данных `application/json`.
- Подписка включает `pull_request`, `issue_comment` и `check_run`. GitHub также отправляет проверочное событие `ping`.
- OpenProject проверяет подпись `X-Hub-Signature-256` с общим секретом вебхука.
- Вебхук использует отдельного пользователя `github-forum-integration` с правами просмотра задач и добавления комментариев только в проекте АСТ «Форум».
- API-токен и секрет хранятся отдельно от репозитория. Не копируйте полный адрес вебхука с параметром `key` в документы, PR или переписку.

## Если PR не появился

Проверьте полный адрес задачи или `OP#PROJ-N` в описании PR. Сохраните описание, чтобы GitHub отправил событие обновления.

В GitHub откройте **Settings → Webhooks → Recent Deliveries**. Успешная доставка получает HTTP 200. HTTP 403 требует проверки токена, выбранного пользователя и секрета.

Прямые ссылки в комментариях добавляются вручную. Штатная интеграция OpenProject 17.8 связывает PR и их статусы; отдельные события `push` и `create` она не обрабатывает.

Официальная инструкция: [GitHub integration — OpenProject](https://www.openproject.org/docs/system-admin-guide/integrations/github-integration/).
