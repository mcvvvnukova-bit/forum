# Единая схема public в базе forum

Миграция `003_public_schema` применена к рабочей **forum** 15 сентября 2026 года
в **18:57:28 UTC / 21:57:28 МСК**. PostgreSQL 18.6, сервер `forum-prod`, контейнер
`outline-postgres-1`, владелец объектов `outline`.

В базе осталась одна прикладная схема — `public`, содержащая **21 таблицу**.
Системные схемы PostgreSQL сохранены. Другие базы, включая `forum_sber_sandbox`,
в область переноса не входят.

## Расположение таблиц

| Назначение | Таблицы в public |
|---|---|
| Учётные записи и внешние идентичности | `users`, `external_identities` |
| Профили и участники | `persons`, `organizations`, `participants`, `participant_memberships` |
| Права и вход | `role_assignments`, `authorization_attempts`, `sessions` |
| Журнал, события, миграции | `audit_events`, `outbox_events`, `schema_migrations` |
| Прежние справочники и данные компаний | `business_segments`, `commercial_roles`, `companies`, `company_okveds`, `company_statuses`, `financial_observations`, `offer_types`, `okveds`, `regions` |

Например, `profiles.persons` теперь называется `public.persons`, а `iam.users` —
`public.users`. Структура строк и бизнес-ограничения не менялись. Физлицо лично
может быть только исполнителем; членство пользователя в нескольких организациях
по-прежнему задаётся отдельными связями.

Перенесены 12 таблиц, их индексы и типы строк, семь функций и принадлежащая outbox
последовательность. В трёх функциях исправлены текстовые ссылки на старую схему.
Схемы `iam`, `profiles`, `audit`, `integration` удалены без `CASCADE` после переноса;
совместимые представления со старыми именами не создавались. Таблицы, функции и
зависимости сохранили свои идентификаторы PostgreSQL и объектные права.

## Резервная копия и повторный запуск

Финальная копия перед применением:
`/opt/backups/forum-public/20260915T185726Z/forum.dump`.

SHA-256: `f7de4f597adf29b44d813c8ef71a924d6b675e494b6fef2f99a313a32ef6e844`.
Она отдельно проверена восстановлением до применения миграции. Каталог доступен
только root; рядом сохранены исходная схема и сравниваемые снимки `before.txt` /
`after.txt` без вывода персональных значений в отчёт.

Применённый комплект, журнал и тестовые результаты:
`/opt/forum-db/releases/20260915-public/`.

Точка входа для владельца схем:

```sh
psql -X -v ON_ERROR_STOP=1 -d forum -f deployment/forum-db/apply-public.psql
```

Скрипт использует транзакцию, блокировку мигратора и журнал
`public.schema_migrations`. Старый `apply-profiles.psql` перенаправляет в этот же
скрипт. Исторические SQL-миграции 001/002 сохранены без переписывания; для новой
установки они выполняются перед 003 в одной транзакции. Ограничение миграции 002
на перенос уже заполненных старых установок остаётся в силе.

## Совместимость приложения

Работающий API использует отдельную базу Sandbox со старой структурой. Полная
интеграция приложения с таблицами `persons` и членствами оставалась отдельной
работой ещё после миграции 002. Теперь её SQL должен использовать `public.*`.
Развёрнутый API этой операцией не обновлялся.

Локальный старый мигратор API теперь прекращает работу при обнаружении
`public.schema_migrations`, чтобы случайный запуск не создавал `iam` повторно.
Файл `deployment/forum-api/grant-runtime.sql` обновлён для основной схемы `public`;
он не подходит для старого Sandbox заменой имени роли.
