# Миграция модульной продуктовой документации: план реализации

> **Для агентных исполнителей:** REQUIRED SUB-SKILL: выполнить план по задачам с контрольными точками. Шаги отмечены чекбоксами (`- [ ]`).

**Цель:** собрать описание продукта в плоской папке `docs/product`, создать единый навигатор и перенести планы реализации в `docs/implementation-plans` без потери решений или битых ссылок.

**Архитектура:** существующие ADR и общая спецификация становятся источниками для 12 модульных документов. `README.md` служит единственной навигационной точкой, а планы хранятся в отдельной папке. Старые каталоги удаляются только после проверки полноты переноса и ссылок.

**Технологии:** Markdown, Git, `rg`, `git diff --check`.

## Общие ограничения

- Все продуктовые документы создаются в плоской папке `docs/product`, без вложенных директорий.
- Один файл описывает один модуль и хранится на русском языке; MVP, B2B и ЭДО допустимы как устойчивые аббревиатуры.
- `docs/product/README.md` содержит ссылки на все модульные файлы и планы реализации.
- Все полезные правила из четырёх ADR и основной продуктовой спецификации переносятся без изменения смысла.
- Договоры, ТЗ, бэклог, брендбук и реестр мероприятий не перемещаются.
- Планы из `docs/plans` и `docs/superpowers/plans` переносятся в `docs/implementation-plans`.
- Ссылки в планах обновляются на новые продуктовые документы.
- Старые папки `docs/adr`, `docs/plans` и `docs/superpowers` удаляются только после успешных проверок.

### Задача 1: Зафиксировать исходное состояние и создать каталог модульных документов

**Файлы:**
- Создать: `docs/product/`
- Читать: `docs/adr/*.md`
- Читать: `docs/superpowers/specs/2026-07-04-construction-order-distribution-platform-design.md`
- Читать: `docs/superpowers/specs/2026-08-10-events-docx-design.md`

**Результат:** проверенный список источников и пустая плоская папка для модульной документации.

- [ ] **Шаг 1: Зафиксировать список и хеши источников**

  Выполнить:

  ```bash
  find docs/adr docs/plans docs/superpowers -type f | LC_ALL=C sort
  shasum -a 256 docs/adr/*.md \
    docs/superpowers/specs/2026-07-04-construction-order-distribution-platform-design.md \
    docs/superpowers/specs/2026-08-10-events-docx-design.md
  ```

  Ожидаемый результат: в списке есть четыре ADR, две спецификации и два плана; хеши записаны в журнал выполнения.

- [ ] **Шаг 2: Создать целевой каталог**

  Выполнить:

  ```bash
  mkdir -p docs/product
  test "$(find docs/product -mindepth 1 -maxdepth 1 | wc -l | tr -d ' ')" = 0
  ```

  Ожидаемый результат: каталог существует и не содержит случайных файлов.

**Результат:** навигатор и документы начала пользовательского пути.

  Включить назначение MVP, границы без публичного каталога, договоров, ЭДО и платежей; последовательность «лендинг → авторизация → заказ → лоты → рассылка → отклик → победитель → пакет сделки → отзывы»; относительные ссылки на все 12 модульных файлов и на оба плана в `../implementation-plans/`.

- [ ] **Шаг 2: Написать документы публичной части и авторизации**

  `landing-page.md` описывает публичные страницы до входа и отсутствие публичных каталогов. `auth-individuals.md` описывает физлиц-исполнителей, email и ограничение сервисными лотами. `auth-legal-entities.md` описывает заказчиков, юрлиц, ИП, пользователей организаций, администратора организации и ручную верификацию до доступа.

- [ ] **Шаг 3: Проверить навигацию**

  Выполнить:

  ```bash
  rg -n '\]\([^)]*\.md\)' docs/product/README.md
  test "$(find docs/product -maxdepth 1 -type f -name '*.md' | wc -l | tr -d ' ')" = 4
  ```

  Ожидаемый результат: README содержит ссылки, в папке четыре Markdown-файла.
