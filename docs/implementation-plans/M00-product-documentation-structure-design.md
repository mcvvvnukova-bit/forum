# Структура продуктовой документации по модулям

**Дата:** 2026-08-11
**Статус:** утверждена для планирования миграции

## Цель

Собрать описание продукта в единой плоской папке `docs/product`, где каждый файл отвечает за конкретный модуль системы. Добавить `docs/product/README.md` как единую точку входа с навигацией и ссылками. Все планы реализации перенести в `docs/implementation-plans`.

## Целевая структура

```text
docs/
├── product/
│   ├── README.md
│   ├── landing-page.md
│   ├── auth-individuals.md
│   ├── auth-legal-entities.md
│   ├── order-publication.md
│   ├── lot-creation.md
│   ├── lot-distribution.md
│   ├── lot-response.md
│   ├── winner-selection.md
│   ├── deal-package.md
│   ├── reviews.md
│   ├── support.md
│   └── analytics.md
└── implementation-plans/
```

Папка `docs/product` не содержит вложенных каталогов. Каждый файл описывает только свой пользовательский модуль: назначение, участников, сценарии, правила, состояния, ограничения MVP и связи с соседними модулями.

## Навигация

`docs/product/README.md` содержит:

- краткое назначение платформы и границы MVP;
- список всех модулей со ссылкой на каждый файл;
- по одной строке о назначении модуля;
- карту основного пользовательского потока: лендинг → авторизация → публикация заказа → лоты → рассылка → отклик → выбор победителя → пакет сделки → отзывы;
- ссылки на планы реализации в `docs/implementation-plans`.

README не повторяет детальные требования модулей. Он служит только навигатором и сводным описанием продукта.

## Распределение существующего содержания

| Новый файл | Содержание и источники |
|---|---|
| `landing-page.md` | Публичная часть, позиционирование, доступные до входа страницы и границы публичной видимости из основной спецификации. |
| `auth-individuals.md` | Регистрация, вход, подтверждение email, профиль и ограничения исполнителей-физлиц. |
| `auth-legal-entities.md` | Регистрация и верификация заказчиков, юрлиц и ИП; пользователи организации, администратор организации и ручная проверка из ADR 0001. |
| `order-publication.md` | Проекты, объекты, заказ-смета, импорт Excel, нормализация, файлы и статусы подготовки заказа. |
| `lot-creation.md` | Формирование, редактирование и модерация лотов; минимальный состав раскрываемых данных из ADR 0003. |
| `lot-distribution.md` | Подбор подходящих исполнителей, видимость опубликованных лотов, избранное, чёрный список и внешние уведомления. |
| `lot-response.md` | Просмотр лота, комментарии и вопросы, структурированное предложение, вложения и правила скрытия контактов до выбора победителя. |
| `winner-selection.md` | Просмотр предложений, выбор одного или нескольких победителей, частичное исполнение и раскрытие контактов. |
| `deal-package.md` | Формирование пакета сделки и граница MVP: без договоров, ЭДО и платежей; решение ADR 0002. |
| `reviews.md` | Подтверждение состоявшейся сделки, отзывы, ответы, модерация и рейтинг. |
| `support.md` | Форма обращения, операционные очереди и роли модератора и администратора, относящиеся к поддержке. |
| `analytics.md` | Операционная аналитика заказчика, исполнителя, модератора и администратора; экспорт предложений. |

Решение ADR 0004 о модерируемой B2B-платформе распределения заказов фиксируется в `README.md` как продуктовая рамка и при необходимости кратко повторяется в связанных модулях без расхождений.

## Планы реализации

В `docs/implementation-plans` находятся оба существующих плана:

- план MVP строительства;
- план экспорта реестра мероприятий в DOCX.

Ссылки внутри планов обновляются на новые пути продуктовых документов. План DOCX не смешивается с описанием функциональности платформы.

## Правила миграции и проверка

- Переносится вся полезная информация из `docs/adr` и `docs/superpowers/specs`; содержательные решения не теряются.
- Устаревшие исходные папки удаляются только после проверки, что содержание перенесено и все ссылки обновлены.
- Документы договоров, технические задания, бэклог, брендбук и реестр мероприятий остаются на своих местах.
- Проверяются Markdown-ссылки, отсутствие ссылок на удалённые пути и чистота `git diff --check`.
- Новые модульные файлы пишутся на русском языке; устойчивые продуктовые аббревиатуры MVP, B2B и ЭДО допустимы.

## Вне объёма

Миграция документации не меняет продуктовые требования, реализацию приложения, договорные документы, данные мероприятий и содержимое брендинга.
