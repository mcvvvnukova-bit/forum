# PROJ-150: локальный профиль зарегистрированного пользователя

Задача: https://roadmap.astforum.ru/work_packages/PROJ-150

## Результат

Отдельное приложение `local-previews/user-profile`, доступное на `http://127.0.0.1:5190/`. React 19, TypeScript, Vite и Primer React 38.37.0. Дизайн развивает ранее согласованную спецификацию профиля от 12 августа: данные только для просмотра, без аватара, отдельного статуса верификации и изменения личных данных в Форуме. Все значения демонстрационные, отображаются полностью. Никакие реальные персональные данные или токены не запрашиваются и не сохраняются.

## Структура

Шапка: локальный логотип АСТ Форум, «Личный кабинет», ссылка с именем пользователя. Боковая навигация ведёт к разделам этой страницы. На мобильном экране она открывается в Primer Dialog. Основной контент: заголовок «Профиль», пояснение об источнике данных, действие «Как изменить данные». Шесть самостоятельных блоков в двух колонках: личные данные / паспорт; адреса / ИНН; контакты / СНИЛС. На узком экране — одна колонка в порядке DOM.

Дополнительные сведения Professional раскрываются отдельной кнопкой: работа и образование; дополнительные документы; дополнительные адреса; предыдущие ФИО и семейное положение. Отсутствующие поля обозначаются «Не передано», поля вне согласованного scope — «Не запрошено». `false` в признаке самозанятости означает «Нет», а не отсутствие данных. При отсутствии maindoc используется priority_doc с корректным названием типа документа. Неизвестный тип не называется паспортом РФ. Место работы не означает наличие доступа к организации.

## Контракт

`buildProfileSections(profile: SberProfile, approvedScopes: readonly string[]): ProfileSection[]` преобразует ответ userinfo в поля для чтения. Технический `sub` не выводится пользователю. Все поля фильтруются по согласованному scope, даже если значение есть во входном объекте. ISO-даты форматируются по-русски; недопустимые даты не выдумываются. Для адреса допускается сборка из документированных частей при отсутствии full_address.

`ProfilePage({profile, approvedScopes, state, onRetry})` поддерживает ready/loading/error. В состояниях loading/error данные предыдущего профиля не выводятся. Повторная попытка в демонстрационном приложении возвращает пример; её текст прямо говорит о демонстрационном поведении. Управление состояниями расположено в отдельном разделе локального макета ниже продуктового интерфейса.

## Источники

- https://developers.sber.ru/docs/ru/sberid/service/scopes : Light и Standart входят в Professional; максимальный пакет не равен реально выданному набору scope.
- https://developers.sber.ru/docs/ru/sberid/service/reqdescription/datareq/overview : данные отсутствуют при отсутствии значения или согласия.
- https://primer.style/product/components/ : только Primer React, Primitives и Octicons.

Figma `WT2IPB0eHD9ULCPENEktwp`: библиотека Primer Web проверена, переменные страницы фирменного стиля прочитаны. Полная семантическая привязка к collection Forum / Light не подтверждена, поэтому используется стандартная тема Primer Light, без переноса брендовых значений.

## Приёмка

Проверки преобразования частичного профиля, scope, false, priority_doc и ISO-дат; проверки пользовательского поведения раскрытия, ошибки и инструкции изменения данных. Typecheck, lint, production build и Primer validator. Во встроенном браузере Codex проверить desktop, tablet, 390 и 320 px, отсутствие горизонтального переполнения, перенос адресов, клавиатуру, Dialog/Escape и возврат фокуса. Подключение к реальному Сбер ID и серверная публикация в объём не входят. Изменения коммитятся в ветку PROJ-150, отправляются в draft PR и связываются с OpenProject согласно AGENTS.md.
