# PROJ-150: локальный профиль зарегистрированного пользователя

Задача: https://roadmap.astforum.ru/work_packages/PROJ-150

## Результат

Отдельное приложение `local-previews/user-profile`, доступное на `http://127.0.0.1:5190/`. React 19, TypeScript, Vite и Primer React 38.37.0. Дизайн развивает ранее согласованную спецификацию профиля от 12 августа: данные только для просмотра, без аватара, отдельного статуса верификации и изменения личных данных в Форуме. Все значения демонстрационные, отображаются полностью. Никакие реальные персональные данные или токены не запрашиваются и не сохраняются.

## Структура

Шапка: локальный логотип АСТ Форум и ссылка с именем пользователя. Боковая навигация ведёт к разделам этой страницы и содержит «Настройки» и «Добавить компанию». Эти два пункта обозначают будущие разделы кабинета: используются штатные неактивные NavList.Item с inactiveText «Раздел пока недоступен», без выдуманных маршрутов. На мобильном экране та же навигация открывается в Primer Dialog. Основной контент: заголовок «Профиль», пояснение об источнике данных, действие «Как изменить данные». Шесть самостоятельных блоков в двух колонках: личные данные / паспорт; адреса / ИНН; контакты / СНИЛС. На узком экране — одна колонка в порядке DOM.

Все карточки страницы профиля видимы сразу: шесть основных блоков, дополнительные документы и другие адреса. Предыдущие ФИО и семейное положение входят в карточку «Личные данные»; отдельной карточки «Другие сведения» нет. Раздел со сворачиванием удалён.

«Работа и образование» открывается на отдельной локальной странице `/profile/work#main`, использующей общую шапку, боковое и мобильное меню. В группе «Мой профиль» добавлена обычная ссылка на эту страницу с aria-current=page при её открытии. На ней отображается карточка с местом работы, должностью, образованием и самозанятостью; карточки основного профиля отсутствуют. Ссылки к его разделам ведут на `/#personal`, `/#identity` и соответствующие якоря. Обычная браузерная навигация сохраняет прямое открытие, перезагрузку и Back/Forward без дополнительной библиотеки маршрутизации.

Отсутствующие поля обозначаются «Не передано», поля вне согласованного scope — «Не запрошено». `false` в признаке самозанятости означает «Нет», а не отсутствие данных. При отсутствии maindoc используется priority_doc с корректным названием типа документа. Неизвестный тип не называется паспортом РФ. Место работы не означает наличие доступа к организации.

## Контракт

`buildProfileSections(profile: SberProfile, approvedScopes: readonly string[]): ProfileSection[]` преобразует ответ userinfo в поля для чтения. Технический `sub` не выводится пользователю. Все поля фильтруются по согласованному scope, даже если значение есть во входном объекте. ISO-даты форматируются по-русски; недопустимые даты не выдумываются. Для адреса допускается сборка из документированных частей при отсутствии full_address.

`ProfilePage({profile, approvedScopes, state, onRetry})` поддерживает ready/loading/error. В состояниях loading/error данные предыдущего профиля не выводятся. Действие повторной попытки вызывает переданный onRetry. Локальное приложение показывает наполненный пример; переключение состояний проверяется тестами компонента.

По браузерным комментариям владельца удалены: «Личный кабинет» из шапки, пояснения карточек ИНН/СНИЛС, легенда «Не передано»/«Не запрошено», весь нижний демонстрационный блок с управлением состояниями, подпись о доступности персональных данных в подвале и вопрос над кнопкой поддержки. Сами значения «Не передано»/«Не запрошено» и кнопка поддержки сохраняются.

## Источники

- https://developers.sber.ru/docs/ru/sberid/service/scopes : Light и Standart входят в Professional; максимальный пакет не равен реально выданному набору scope.
- https://developers.sber.ru/docs/ru/sberid/service/reqdescription/datareq/overview : данные отсутствуют при отсутствии значения или согласия.
- https://primer.style/product/components/ : только Primer React, Primitives и Octicons.

Figma `WT2IPB0eHD9ULCPENEktwp`: библиотека Primer Web проверена, переменные страницы фирменного стиля прочитаны. Полная семантическая привязка к collection Forum / Light не подтверждена, поэтому используется стандартная тема Primer Light, без переноса брендовых значений.

## Приёмка

Проверки преобразования частичного профиля, scope, false, priority_doc и ISO-дат; проверки пользовательского поведения раскрытия, ошибки и инструкции изменения данных. Typecheck, lint, production build и Primer validator. Во встроенном браузере Codex проверить desktop, tablet, 390 и 320 px, отсутствие горизонтального переполнения, перенос адресов, клавиатуру, Dialog/Escape и возврат фокуса. Подключение к реальному Сбер ID и серверная публикация в объём не входят. Изменения коммитятся в ветку PROJ-150, отправляются в draft PR и связываются с OpenProject согласно AGENTS.md.
