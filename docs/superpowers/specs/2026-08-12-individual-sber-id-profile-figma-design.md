# Профиль физического лица из Сбер ID в Figma

## Цель

Добавить на страницу Figma `ЛК физ лица` отдельный desktop-фрейм профиля авторизованного физического лица. Экран открывается по ссылке `Алексей Смирнов` в шапке существующего личного кабинета и показывает доступные системе данные Сбер ID без возможности редактирования.

## Подтверждённый сценарий

- Пользователь уже успешно идентифицирован через Сбер ID и зарегистрирован на площадке; отдельный платформенный статус верификации не используется.
- Экран открывается из существующего фрейма ЛК по нажатию на имя пользователя в шапке.
- Данные получены по заранее согласованным расширенным scope Сбер ID, включая Professional.
- Все значения отображаются полностью, без маскирования.
- Профиль доступен только для чтения; изменение данных внутри ЛК отсутствует.
- Аватар не используется.
- Лейблы `Сбер ID`, `Личность подтверждена` и другие дублирующие подтверждения в шапке не добавляются.

## Компоновка

- Новый фрейм имеет размер `1440 × 1100` px и размещается на той же Figma-странице рядом с текущим экраном.
- Шапка и левая навигация повторяют актуальное состояние существующего ЛК.
- В левом меню нет активного пункта: профиль открыт из глобальной ссылки в шапке, а не из рабочего раздела.
- Основной контент начинается с заголовка `Профиль` и пояснения `Данные получены из Сбер ID и доступны только для просмотра`.
- Справа от заголовка располагается ссылка `Изменить в Сбер ID` с обозначением внешнего перехода.
- Контент разбит на шесть самостоятельных блоков Primer в двухколоночной сетке.
- Порядок блоков фиксирован построчно: `Личные данные / Паспорт`, `Адреса / ИНН`, `Контакты / СНИЛС`.
- Блоки используют строки `название поля → значение`, разделители и адаптивную сетку; значения не выглядят как редактируемые поля ввода.

## Компоненты и дизайн-система

- Primer остаётся единственной UI-системой.
- Шапка, ссылки, навигация, заголовки и контейнеры переиспользуют существующие библиотечные Primer instances или совместимые композиции из текущего ЛК.
- Системные иконки берутся только из опубликованной библиотеки Primer Octicons; локальные компоненты иконок не создаются.
- Брендовые цвета берутся только из коллекции `FORUM / Dashboard Tokens`, режим `Light`.
- Цвета, типографика, интервалы, радиусы и границы привязываются к доступным семантическим переменным; безопасный Primer Light fallback допускается только при отсутствии однозначного Forum-сопоставления.
- Библиотечные компоненты не detach.

## Поведение и переходы

- Ссылка `Алексей Смирнов` в существующем фрейме получает prototype-навигацию к новому фрейму профиля по клику.
- Имя пользователя в шапке профиля остаётся ссылкой и может указывать на текущий фрейм без дополнительного выпадающего меню.
- `Изменить в Сбер ID` оформляется как внешний переход; редактирование непосредственно на экране отсутствует.
- Рабочие пункты левого меню сохраняют переходы в соответствующие разделы, но ни один не отмечен как текущий на профиле.
- Порядок фокуса: уведомления → имя пользователя → навигация → поддержка → заголовок → `Изменить в Сбер ID` → информационные карточки.

## Адаптивность

- Desktop: постоянная боковая панель и две колонки блоков.
- При сужении контента блоки складываются в одну колонку в порядке: личные данные, паспорт, адреса, ИНН, контакты, СНИЛС.
- На ширине mobile навигация открывается как drawer; значения адресов переносятся, не обрезаются и не превращаются в горизонтальный скролл.
- В рамках задачи создаётся один desktop-фрейм; адаптивное поведение фиксируется в существующей спецификации страницы.

## Ограничения и обработка данных

- Паспорт, ИНН, СНИЛС и адреса отображаются только при наличии соответствующих согласованных scope и согласия пользователя.
- Если отдельное значение не пришло, продукт должен показывать нейтральное `Нет данных`, а не выдумывать или восстанавливать значение.
- Макет показывает успешное наполненное состояние; loading, ошибка загрузки и отсутствие согласия остаются состояниями реализации, но не требуют отдельных фреймов в текущем объёме.
- Балансы, карты, счета, вклады и другие банковские данные не отображаются: Сбер ID не предоставляет их партнёру в этом сценарии.

## Критерии готовности

- На странице `ЛК физ лица` создан отдельный фрейм `1440 × 1100` с названием, однозначно обозначающим профиль Сбер ID.
- Шапка и меню визуально согласованы с актуальным ЛК; аватар и подтверждающие лейблы отсутствуют.
- На экране присутствуют шесть утверждённых групп и все демонстрационные значения; общего блока `Документы` нет.
- В desktop-сетке блоки расположены тремя строками: `Личные данные / Паспорт`, `Адреса / ИНН`, `Контакты / СНИЛС`.
- Данные визуально представлены как read-only, а единственное изменение вынесено во внешнюю ссылку.
- Ссылка с именем на исходном экране ведёт к новому фрейму в prototype-режиме.
- Все Primer и Octicons остаются связанными библиотечными instances.
- Используется только режим `Forum / Light`; нет жёстко заданных цветов или типографики при наличии токена.
- Нет обрезанного текста, наложений, случайных локальных компонентов или элементов вне фрейма.
- Итог проверен структурно и визуально в Figma.
