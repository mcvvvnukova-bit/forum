# Экран «Обзор», собранный только из компонентов Primer

## Цель

Создать в Figma рядом с исходным экраном `Desktop / Обзор / Верифицирована` отдельный фрейм с теми же данными и пользовательскими задачами, но с максимально строгим использованием официальной Figma-библиотеки Primer.

## Подтверждённый подход

Выбран вариант 2: максимальная компонентная чистота.

- Корневой технический фрейм экрана — допустимое исключение, необходимое для размещения интерфейса на холсте.
- Фирменный логотип АСТ «Форум» сохраняется как брендовый компонент и является единственным содержательным исключением.
- Все остальные смысловые и интерактивные блоки должны быть экземплярами официальных компонентов Primer.
- Локальные компоненты `Primer / FORUM / ...`, новые локальные компоненты и копии компонентов Primer не используются.
- Обычные текстовые и графические слои вне официальных компонентов Primer не используются.

## Содержание экрана

Сохраняются данные исходного макета: организация `ООО «Стройконтур»`, статус `Верифицирована`, пользователь `Алексей Смирнов`, навигация кабинета, заголовок `Обзор`, действия `Разместить заказ` и `Найти заказы`, четыре показателя, три записи `Требует внимания`, списки `Мои заказы` и `Подходящие заказы`.

## Компонентная архитектура

Используются доступные официальные компоненты Primer: `Heading`, `Button`, `StateLabel`, `NavList.GroupHeading`, `NavList.Item`, `ActionList.Item` и другие официальные экземпляры из подключённой библиотеки. Если библиотека не предоставляет `PageLayout`, `AppHeader` или `Card`, композиция упрощается и официальные экземпляры размещаются непосредственно в техническом корневом фрейме.

## Визуальные ограничения

- Размер нового фрейма: 1440 × 1100 px, как у исходника.
- Имя: `Desktop / Обзор / Primer — strict`.
- Сохраняется иерархия: header, sidebar, main content, показатели, внимание, два списка заказов.
- Визуальный язык определяется официальными компонентами Primer; точное воспроизведение локальной оранжевой стилизации не требуется.
- Шрифт определяется официальными стилями компонентов Primer.

## Правила содержимого экземпляров

1. Для текста и вариантов сначала используются `instance.setProperties()` и официальные component properties.
2. Если официальный компонент не публикует текст как component property, разрешён прямой `characters` override только у `TEXT`-потомка связанного официального Primer instance.
3. Перед таким override загружается фактический шрифт текстового слоя.
4. Экземпляры не detach; внутренние графические слои не редактируются; обычные текстовые слои вне экземпляров не создаются.

## Проверка результата

Результат готов, если новый фрейм существует отдельно, исходный фрейм не изменён, брендовый логотип сохранён, все остальные смысловые элементы остаются связанными экземплярами официальной библиотеки Primer, отсутствуют локальные `Primer / FORUM`, detach, самодельные аналоги, плейсхолдеры, обрезанный текст и наложения.

Итоговый аудит должен перечислить официальные компоненты и два допустимых исключения: корневой технический фрейм и брендовый логотип.
