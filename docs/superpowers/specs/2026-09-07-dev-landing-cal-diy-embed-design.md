# Виджет записи на демо на dev.astforum.ru

## Задача и согласованное решение

Пользователь подтвердил штатное всплывающее окно Cal.diy, открывающееся по нажатию на существующую кнопку «Выбрать время». Лендинг остаётся открытым, внешний вид кнопки и остальных секций не меняется.

- Лендинг: `https://dev.astforum.ru`.
- Запись: `https://cal.astforum.ru/demo/60min`.
- Тип события, указанный пользователем: `eventId=3`; namespace: `60min`.
- Переданная ссылка `/event-types?dialog=embed...` относится к настройкам администратора. Встраивается публичная запись `demo/60min`, а не административная страница.

## Варианты

1. **Штатный виджет Cal.diy — выбран пользователем.** Используем существующий механизм всплывающей записи и его адаптивное окно.
2. Собственное модальное окно с iframe — отклонено как ненужная дополнительная реализация управления окном.

## Реализация

Исходники лендинга расположены в `deployment/dev-landing`. Кнопка находится в `src/landing/LandingApp.tsx` и сейчас ссылается на заглушку `/api/demo-request`.

Подключение виджета изолируется в небольшом модуле рядом с лендингом. Используются штатные API и скрипт встраивания установленного Cal.diy с явно заданным origin `https://cal.astforum.ru`. Скрипт загружается однократно. Секреты, административная сессия и API-ключи для встраивания не нужны.

При обычном нажатии кнопки открывается окно записи на `demo/60min`; страница лендинга не перезагружается. Повторное нажатие после закрытия вновь открывает виджет без создания дубликатов. Если скрипт не загрузился, остаётся доступен переход на публичную страницу записи вместо неработающей кнопки.

Верхние ссылки «Записаться на демо» продолжают прокручивать лендинг к секции демо. Парольная защита dev-сайта, остальные кнопки и вёрстка сохраняются. Если действующая CSP блокирует виджет, разрешается только необходимый origin Cal.diy; защитные заголовки целиком не отключаются.

## Проверки и публикация

- Проверить, что публичное событие и скрипт встраивания доступны.
- Покрыть тестами подключение нужного origin и события, открытие по кнопке и отсутствие дублирующей инициализации.
- Выполнить проверку TypeScript, существующие тесты и production-сборку лендинга.
- В браузере проверить открытие и закрытие окна на настольной и мобильной ширине, отсутствие ошибок и сохранение вёрстки.
- Опубликовать изменения только на `dev.astforum.ru` и повторить проверку после входа через существующую парольную защиту.
- Проверка не создаёт реальную бронь и не отправляет уведомления клиентам.

## Вне задачи

Не меняются настройки события, пользователи Cal.diy, распределение менеджеров, интеграции Битрикс24/Яндекс, SMTP и основной сайт `astforum.ru`. Собственный интерфейс календаря не разрабатывается.
