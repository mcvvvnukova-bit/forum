# Публикация pgAdmin 4 для АСТ Форум

Дата: 2026-08-28

## Цель

Предоставить небольшой команде доступ к установленному pgAdmin 4 из обычного
браузера по адресу `https://pg.astforum.ru`, без VPN и без дополнительного слоя
авторизации перед pgAdmin. Создать две отдельные учётные записи pgAdmin с полным
доступом к базе данных АСТ Форум:

- `admin@astforum.ru`;
- `ceo@astforum.ru`.

PostgreSQL при этом не должен становиться доступным из интернета.

## Текущее состояние

- Сервер: Debian 13, публичный адрес `84.47.165.130`.
- Доступ к серверу выполняется по SSH через алиас `forum-prod`.
- pgAdmin 4 версии 9.17 запущен в Docker Compose из `/opt/pgadmin`.
- Веб-порт pgAdmin опубликован только на `127.0.0.1:5050`.
- Контейнер pgAdmin подключён к внутренней сети Outline и обращается к
  PostgreSQL по имени `postgres`.
- В pgAdmin уже существует администратор `admin@astforum.ru` и зарегистрировано
  подключение `AST Forum / Outline PostgreSQL`.
- Caddy обслуживает публичные HTTP/HTTPS-запросы сервера.
- DNS-запись для `pg.astforum.ru` отсутствует; зона `astforum.ru` управляется в
  REG.RU.

## Архитектура

1. В REG.RU создаётся DNS-запись `A` для `pg.astforum.ru`, указывающая на
   `84.47.165.130`. Рекомендуемый TTL на время развёртывания — 300 секунд.
2. В активную конфигурацию Caddy добавляется отдельный виртуальный хост
   `pg.astforum.ru`.
3. Caddy получает и обновляет публичный TLS-сертификат и перенаправляет HTTP на
   HTTPS.
4. Caddy проксирует HTTPS-запросы к `pgadmin:5050` через общую внутреннюю
   Docker-сеть. Точный способ подключения выбирается после проверки фактически
   запущенного Compose-проекта Caddy; существующая схема публикации Outline не
   меняется.
5. Привязка `127.0.0.1:5050` сохраняется как аварийный доступ через SSH-туннель.
6. Порты PostgreSQL и внутренние порты контейнеров не публикуются во внешнюю
   сеть. Снаружи доступны только уже используемые сервером порты 80 и 443.

Поток запроса:

`браузер → HTTPS pg.astforum.ru → Caddy → pgAdmin:5050 → PostgreSQL во внутренней сети`

## Учётные записи и доступ к базе

- `admin@astforum.ru` сохраняется как администратор pgAdmin.
- Создаётся отдельный администратор pgAdmin `ceo@astforum.ru`.
- Для каждой учётной записи генерируется отдельный случайный стойкий пароль.
- Пароли входа в pgAdmin не выводятся в журналы, не записываются в репозиторий
  и хранятся на сервере в отдельных root-доступных файлах с правами не шире
  `0400`.
- Обоим пользователям отдельно регистрируется подключение
  `AST Forum / Outline PostgreSQL`.
- Оба подключения используют существующую роль PostgreSQL `outline`, поэтому
  оба пользователя получают одинаковый полный доступ к целевой базе, как
  запросил владелец системы.
- Доступ к другим базам или системному хосту не предоставляется.

Раздельные учётные записи pgAdmin обеспечивают независимый вход и позволяют в
дальнейшем отключить одного пользователя без отключения второго. Общая роль
PostgreSQL означает, что действия пользователей внутри базы не разделяются по
ролям БД и не могут быть надёжно атрибутированы конкретному человеку средствами
PostgreSQL. Это осознанный компромисс принятого требования о полном одинаковом
доступе.

## Защита публичного интерфейса

- Перед pgAdmin не добавляется Basic Auth, VPN, Cloudflare Access или иной
  дополнительный шлюз авторизации.
- Весь браузерный трафик обслуживается только по HTTPS; безопасные параметры
  cookies и встроенная защита входа pgAdmin остаются включёнными.
- Caddy добавляет уместные защитные HTTP-заголовки, не нарушающие работу
  pgAdmin.
- Контейнер pgAdmin сохраняет текущие ограничения: запуск от непривилегированного
  пользователя, `cap_drop: ALL` и `no-new-privileges`.
- Прямой публичный доступ к порту 5050 не открывается.
- Секрет подключения PostgreSQL хранится в отдельном `.pgpass` каждого
  пользователя pgAdmin с владельцем процесса pgAdmin и правами `0400`; он не
  передаётся браузеру в открытом виде.

## Развёртывание и откат

Перед изменениями выполняются read-only проверки фактических контейнеров,
Docker-сетей, пробросов портов и активной конфигурации Caddy. Исходная
конфигурация Caddy, Compose-конфигурация pgAdmin и конфигурационная база pgAdmin
резервируются на сервере с ограниченными правами.

Изменения применяются идемпотентным root-скриптом. До перезапуска проверяются
синтаксис Compose-конфигурации и конфигурация Caddy. При ошибке запуска или
проверки работоспособности восстанавливаются сохранённые конфигурации и
предыдущее состояние контейнеров. Данные PostgreSQL не изменяются и не входят в
область миграции.

DNS-запись в REG.RU является внешним предварительным условием для автоматической
выдачи TLS-сертификата. Серверную часть можно подготовить заранее, но публичная
приёмка завершается только после распространения DNS.

## Проверка и критерии приёмки

- `pg.astforum.ru` разрешается в `84.47.165.130`.
- `http://pg.astforum.ru` перенаправляется на HTTPS.
- `https://pg.astforum.ru` предъявляет доверенный сертификат для этого имени и
  открывает страницу входа pgAdmin без ошибок прокси.
- Порт 5050 доступен только через loopback-интерфейс сервера; порт PostgreSQL не
  доступен из интернета.
- Вход успешно выполняется отдельно под `admin@astforum.ru` и
  `ceo@astforum.ru`.
- У обоих пользователей видно подключение `AST Forum / Outline PostgreSQL`.
- Под каждой учётной записью выполняются проверочный `SELECT current_database()`
  и безопасная транзакционная проверка полного доступа с обязательным
  `ROLLBACK`, не оставляющая объектов или данных.
- После публикации сохраняется резервный доступ по SSH-туннелю к
  `127.0.0.1:5050`.
- Существующий сайт и Outline продолжают отвечать по своим текущим адресам.

## Вне области работ

- Публикация PostgreSQL в интернет.
- Дополнительная авторизация перед pgAdmin, VPN или обязательная двухфакторная
  аутентификация.
- Создание отдельных ролей PostgreSQL для персонального аудита действий.
- Изменение данных, схемы или ролей приложения Outline.
- Перенос DNS-зоны с REG.RU к другому провайдеру.
