# Автоматический цикл исправлений с лимитом 12 часов

## Контекст

Текущий контрольный процесс разрешает одну автоматическую финальную волну исправлений и одну повторную проверку. Если проверка находит новые или неустранённые замечания, процесс останавливается и ждёт отдельного разрешения пользователя. Это ограничение заменяется автоматическим циклом, ограниченным по времени.

Исторические отчёты о уже завершённых циклах не переписываются: они фиксируют правила, действовавшие в момент выполнения. Новое правило применяется к текущей незавершённой работе и последующим циклам.

## Новое правило

После запуска контрольного процесса автоматически повторяется последовательность:

1. независимая проверка результата;
2. исправление всех подтверждённых блокирующих или иных actionable-замечаний;
3. релевантные тесты и проверки целостности;
4. повторная независимая проверка.

Цикл завершается при первом из двух событий:

- проверка не оставила нерешённых actionable-замечаний и обязательные тесты прошли;
- истёк 12-часовой лимит wall-clock времени, отсчитываемый от запуска цикла.

Между волнами исправлений дополнительное подтверждение пользователя не требуется.

## Контроль времени

При запуске фиксируются `started_at` и `deadline = started_at + 12 часов`. Перед началом каждой новой волны исправлений процесс проверяет дедлайн.

После наступления дедлайна:

- новая волна исправлений не начинается;
- уже запущенная безопасная проверка или тестовая команда может завершиться, чтобы не потерять диагностический результат;
- изменения не сливаются и не публикуются автоматически;
- пользователю передаётся итоговый статус.

Таким образом, 12 часов — предел для автоматического начала новых исправлений. Завершение уже выполняющейся безопасной проверки может незначительно выйти за этот предел.

## Отчёт по завершении

При успешном завершении отчёт содержит финальный commit, результаты обязательных тестов и заключение повторной проверки.

При остановке по времени отчёт содержит:

- длительность и причину остановки;
- выполненные и проверенные изменения;
- последний известный результат тестов;
- оставшиеся замечания с уровнем важности;
- безопасный следующий шаг.

Остановка по тайм-ауту не считается успешным завершением и не делает ветку готовой к слиянию.

## Применение к текущей ветке

Прежнее решение «не запускать вторую автоматическую fix-wave» для активного цикла `okved-parser-residual-input-hardening` считается отменённым этим правилом. После подготовки плана процесс может автоматически исправлять два оставшихся Important-замечания и повторять проверку до чистого результата либо до истечения 12 часов.

## Проверка правила

Контроль процесса должен подтверждать четыре сценария:

1. чистая повторная проверка завершает цикл до дедлайна;
2. замечания до дедлайна запускают следующую автоматическую волну;
3. наступивший дедлайн запрещает запуск новой волны;
4. остановка по дедлайну формирует отчёт и не помечает ветку готовой к слиянию.
