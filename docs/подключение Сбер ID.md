# Подключение Сбер ID для проверки физического лица

Дата сбора информации: 27 июля 2026.

## Краткий вывод

Для проверки пользователя-физического лица через Сбер нужно подключать сервис **Сбер ID**. Это сервис аутентификации, входа и регистрации пользователей на сайтах и в мобильных приложениях партнеров Сбера. Для партнерской системы он дает верифицированные данные пользователя, защиту от фрода и возможность использовать профильные данные по разрешенным `scope`.

Сбер ID предназначен для физических лиц. Если нужно проверять юридических лиц или ИП, Сбер отдельно указывает на другой продукт — **СберБизнес ID**.

## Условия подключения

Подключить Сбер ID может любой сайт или приложение, зарегистрированные на территории РФ. Быть действующим партнером СберБанка необязательно.

Базовый порядок подключения:

1. Зарегистрировать организацию на портале Сбер ID.
2. Заполнить данные об организации и пройти модерацию.
3. Согласиться с условиями подключения и подписать документы.
4. Получить `Client ID`, `Client Secret` и выпустить сертификат безопасности.
5. Реализовать на стороне системы партнера получение кода авторизации, токенов и данных пользователя.
6. Реализовать подтверждение успешного входа пользователя.
7. Разместить интерфейс входа по Сбер ID с учетом дизайн-требований.

По публичной странице продукта подключение и использование Сбер ID бесплатные. Сбер также указывает бесплатное сопровождение после интеграции.

## Как работает проверка пользователя

Интеграция строится по сценарию OAuth 2.0 / OpenID Connect:

1. Пользователь нажимает кнопку входа по Сбер ID в системе партнера.
2. Система партнера генерирует `state` и `nonce`.
3. Пользователь переходит на страницу аутентификации Сбер ID или подтверждает вход в приложении СберБанк Онлайн.
4. Пользователь подтверждает согласие на передачу данных, если активного согласия еще нет.
5. Сбер возвращает `auth_code` на зарегистрированный `redirect_uri`.
6. Backend партнера обменивает `auth_code` на `access_token` и `id_token`.
7. Backend партнера проверяет `state`, `nonce`, `aud` и другие параметры токена.
8. Backend партнера запрашивает профиль пользователя через `userinfo`.
9. Партнер авторизует или регистрирует пользователя в своей системе.
10. На промышленном контуре партнер отправляет событие об успешном завершении авторизации.

Важно: Сбер ID нельзя реализовывать через `iFrame`. Для сценариев с риском перехвата `auth_code` нужно использовать PKCE.

## Какие данные можно получить для верификации

Данные выдаются по `scope`, которые разрешены системе партнера при регистрации в банке. Сбер описывает три пакета данных:

| Пакет | Примеры данных |
| --- | --- |
| Light | `sub`, email, номер телефона |
| Standart | дата рождения, ФИО, пол |
| Professional | паспортные данные, ИНН, СНИЛС, водительское удостоверение, загранпаспорт, приоритетный документ, гражданство, место рождения, адрес регистрации и другие данные |

Для полноценной проверки физического лица обычно потребуется не только `openid`, но и набор данных из `Standart` или `Professional`. Конкретные `scope` нужно согласовать и получить при подключении.

Если по клиенту нет запрошенных данных, клиент запретил передачу данных или партнер запросил неразрешенный `scope`, соответствующие данные не будут переданы либо вернется ошибка `invalid_scope`.

## Ограничения и требования, которые нужно учитывать

- Система партнера должна быть зарегистрирована у Сбера и иметь выданные `Client ID`, `Client Secret` и сертификат.
- `redirect_uri` должен быть зарегистрирован у Сбера и совпадать при запросе токена.
- Значение `openid` обязательно и должно быть первым в параметре `scope`.
- `state` используется для защиты от CSRF, `nonce` — для защиты от replay-атак.
- Партнер должен проверять `aud` в `id_token`: значение должно совпадать с его `client_id`.
- Для идентификации пользователя Сбер рекомендует использовать `sub`, а также учитывать `alt_sub`, если он приходит.
- Пользователь может отказаться от передачи согласий. В этом случае возвращается ошибка `access_denied`.
- Сервис партнера не получает доступ к приложению СберБанк Онлайн, картам, счетам, вкладам и балансам пользователя.
- Сбер ID сейчас поддерживает вход и регистрацию по российским номерам телефона.

## Рекомендация для интеграции

Для сценария регистрации пользователя в системе стоит начать с минимального входа по Сбер ID и сразу определить, какой уровень проверки нужен бизнес-процессу:

- если достаточно подтвердить устойчивый идентификатор, телефон и email — начать с пакета Light;
- если нужна проверка ФИО и даты рождения — согласовывать Standart;
- если нужна юридически значимая идентификация по документам — заранее согласовывать Professional и требования к обработке персональных данных.

Перед разработкой нужно отдельно проверить договорные условия, требования к персональным данным и состав `scope`, который Сбер готов выдать конкретной системе.
