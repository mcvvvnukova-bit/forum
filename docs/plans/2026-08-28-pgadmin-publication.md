# Public pgAdmin 4 Access Implementation Plan

Исторический технический план от 2026-08-28. Статусы и результаты ниже относятся к исходному наблюдению, не подтверждают текущий runtime и не разрешают новый запуск или публикацию. Перед исполнением сверить актуальный код, канонические требования и отдельно разрешённую задачу.

Происхождение: `docs/superpowers/plans/2026-08-28-pgadmin-publication.md`, SHA-256 `0e61e13012c707f030dced565251edf003092b775746210ea789b30d7a31439c`. Проверка сохранения указана в [реестре миграции](../../artifacts/repository-audits/document-migration-manifest.json).

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish the existing pgAdmin 4 instance at `https://pg.astforum.ru` and provision `admin@astforum.ru` and `ceo@astforum.ru` as separate pgAdmin administrators with full access to the Outline PostgreSQL database.

**Architecture:** The existing Caddy edge terminates public TLS and reverse-proxies to pgAdmin over the Docker network already shared by Caddy and pgAdmin. pgAdmin remains bound to `127.0.0.1:5050` for SSH-tunnel fallback, while PostgreSQL remains reachable only inside Docker. Each pgAdmin login has its own password and server registration; both registrations use the existing PostgreSQL role `outline` as explicitly approved.

**Tech Stack:** Debian 13, Docker Engine, Docker Compose v2, Caddy 2, pgAdmin 4 9.17, PostgreSQL 18, REG.RU DNS, Bash, curl, OpenSSL.

**Spec:** [продуктовый источник](https://docs.astforum.ru/doc/istochnik-06102026-publikaciya-pgadmin-4-dlya-ast-forum-49193771-UabZHd1H8g)

## Global Constraints

- Public URL is exactly `https://pg.astforum.ru`.
- DNS `A pg.astforum.ru` must resolve to `84.47.165.130`.
- Do not publish PostgreSQL, Redis, or container port 5050 on a non-loopback host address.
- Keep `127.0.0.1:5050` available for the existing SSH-tunnel fallback.
- Do not add Basic Auth, VPN, Cloudflare Access, or another authentication layer before pgAdmin.
- Keep the image pinned to `dpage/pgadmin4:9.17`.
- Preserve `cap_drop: ALL`, `no-new-privileges`, UID/GID 5050 ownership, and the existing internal PostgreSQL connection.
- Provision `admin@astforum.ru` and `ceo@astforum.ru` as active pgAdmin Administrators.
- Give both pgAdmin users the `AST Forum / Outline PostgreSQL` registration backed by PostgreSQL role `outline`.
- Generate a different random pgAdmin login password for each user and never print either password in command output or logs.
- Do not modify PostgreSQL data, schema, application roles, the existing Outline site, or unrelated server configuration.

## File Structure

- Read and back up remotely: `/opt/outline/docker-compose.yml` — active Outline/Caddy Compose definition.
- Modify remotely: `/opt/outline/Caddyfile` — add the `pg.astforum.ru` virtual host.
- Read and back up remotely: `/opt/pgadmin/compose.yaml` — pgAdmin service, loopback port and Docker networks.
- Read remotely: `/opt/pgadmin/servers.json` — canonical PostgreSQL server definition imported for each pgAdmin user.
- Create remotely: `/opt/pgadmin/secrets/ceo_password` — root-readable pgAdmin password for `ceo@astforum.ru`.
- Preserve remotely: `/opt/pgadmin/secrets/admin_password` — existing root-readable password for `admin@astforum.ru`.
- Create remotely: `/var/lib/pgadmin/storage/ceo_astforum.ru/.pgpass` inside the pgAdmin data volume — pgAdmin-readable PostgreSQL password file for the CEO registration.
- Create remotely: `/opt/backups/pgadmin-publication/` with a UTC-dated child directory generated by `date -u +%Y%m%dT%H%M%SZ` — restricted rollback snapshot of the touched configuration and pgAdmin SQLite database.
- Create locally only during the edit: a directory generated by `mktemp -d /tmp/astforum-pgadmin-publication.XXXXXX` — downloaded active Caddyfile edited with `apply_patch`, validated, uploaded, and then removed.

- [ ] **Step 2: Add or synchronize `ceo@astforum.ru` as an active Administrator**

```bash
  /venv/bin/python3 /pgadmin4/setup.py get-users --username ceo@astforum.ru --json \

```

Expected: the command succeeds without printing the password.
