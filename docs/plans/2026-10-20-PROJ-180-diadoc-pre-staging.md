# PROJ-180: первый пакет проверки организаций до доступа Контура

Источник: `docs/plans/2026-10-11-001-feat-diadoc-organization-verification-plan.md` и поручение владельца начать первый пакет (модель → API → UI → имитатор и тесты).

Исполняется на `origin/main` 5937f25d. Исходный план сохраняется без изменений. Задача: https://roadmap.astforum.ru/work_packages/PROJ-180, родитель PROJ-5.

## Границы пакета

Подготовить additive-хранилище проверок, собственный API, интерфейс двух путей и клиент Диадока с отдельным локальным имитатором. Никакие результаты этого пакета не выдают membership, authority, business role или юридическое разрешение. Регистрация заявления, криптографическая проверка КЭП/МЧД, OIDC-linking и настоящий вход в Контур выполняются следующими пакетами общего плана. Кнопки не изображают завершённую юридическую регистрацию.

В production функция выключена по умолчанию. Имитация располагается только в test/diagnostics, не выбирается параметром пользовательского запроса и не включается переменной окружения production. Реальный клиент вызывается только с серверным пользовательским токеном, которого пока нет; API по умолчанию возвращает необходимость подключения либо подписи. Отсутствие Диадока не блокирует независимый путь КЭП.

## Контракт

- `GET /api/me/organizations/verification/options`: собственная сессия; `{userId,enabled}`.
- `GET /api/me/organizations/verification?inn=...`: собственная сохранённая организация; `{userId,item:null|Verification}`.
- `POST /api/me/organizations/verification`: точный JSON `{inn,method:'diadoc'|'kep',requestId:UUID}`; собственная сессия и точный Origin. Повтор requestId возвращает ту же попытку; другое содержание с тем же requestId — 409. GET восстанавливает последнюю попытку; неизвестный/чужой ИНН — одинаковый 404.
- DTO: id, inn, method, status, checkedAt, expiresAt, source, reason, минимальные реквизиты/технические права. `legalPermissions` всегда `{registerCompany:false,submitTender:false}`. Никаких токенов, email, полного roster или чужих участников.
- Статусы: `checking`, `connection_required`, `signature_required`, `access_confirmed`, `access_denied`, `unavailable`, `selection_required`. Последние четыре — технический результат источника, не юридическое заключение. Несколько КПП/ящиков требуют выбора в следующем пакете, не произвольного первого ящика.

## Задачи

1. Additive-миграция `008_organization_verifications`, ограниченное хранение попыток и результатов, аудит начала/окончания, runtime grants и обратная инструкция. Тесты: сохранение/повтор/конкуренция, чужой ИНН, конфликт requestId, отсутствие новых корпоративных прав.
2. Контроллер и конфигурация feature flag; provider seam с закрытым по умолчанию источником, одноразовое выполнение, CAS завершения. Тесты через createApp: Origin/session/строгий ввод, no-store, default-off, сохранение после рестарта приложения, ошибки без утечки секретов.
3. Клиент Диадока: `GetMyOrganizations?autoRegister=false`, только явный `IsEmployee=true`, затем собственный `GetMyEmployee` по единственному проверенному ящику. Неизвестная блокировка/permission → отказ от положительного подтверждения; 401/402/403/404/409/5xx/timeout и неверные данные имеют разные технические причины. Локальный HTTP-имитатор проверяет реальные запросы клиента. Никаких записывающих методов.
4. Primer UI: раскрытие проверки своей строки, два пути, загрузка результата, повтор с тем же requestId после неопределённого ответа, отдельное техническое подтверждение и юридический допуск. Смена пользователя/закрытие панели прерывают и игнорируют старые ответы. Тесты и browser QA desktop/mobile/keyboard.
5. Шлюз с точным allowlist новых путей; локальный сквозной стенд с отдельной БД; проверки API/web/Primer/layout и итоговое независимое ревью. Коммиты, push, PR с OP#PROJ-180 и OP#PROJ-5; проверка связи в OpenProject. Публикация и merge не входят.

## Готовность и оставшиеся зависимости

Рабочая собственная часть с реальным PostgreSQL и HTTP-имитатором, сохранением/повторным чтением, изоляцией пользователей и нулевой выдачей корпоративных прав. Зафиксированы проверки и ограничения. Фикстуры не подтверждают контракт Контура: staging OIDC, побочные эффекты API, optional-поля, лицензирование, безопасная последовательность методов и все юридические источники остаются внешними зависимостями.
