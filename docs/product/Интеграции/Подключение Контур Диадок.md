# Подключение Контур.Диадока для входа и подтверждения связи с организацией

Дата сбора информации: **11 августа 2026 года**.

Страница для технологических партнеров Контура - https://kontur.ru/partner-tech

## Краткий вывод

Для входа юридических лиц и индивидуальных предпринимателей в АСТ «Форум» подходит **Контур.Диадок API** с авторизацией через OpenID Connect.

После входа система может получить список организаций Диадока, к которым у пользователя есть доступ. Это подтверждает связь пользователя с организацией на уровне доступа к её ящику Диадока.

Такой вход **не доказывает**, что пользователь вправе регистрировать организацию на платформе, подписывать документы или действовать без доверенности. Для этого требуется отдельная проверка полномочий: КЭП и, для представителя, машиночитаемая доверенность (МЧД) либо иной юридически согласованный способ.

Контур.Фокус остаётся отдельным сервисом для проверки реквизитов, статуса и рисков организации. Он не заменяет авторизацию и проверку полномочий человека.

## Что подтверждает каждый этап

| Этап | Что подтверждается | Чего не подтверждает |
| --- | --- | --- |
| Вход через OpenID Connect Диадока | Пользователь успешно прошёл аутентификацию в Диадоке | Право действовать от имени компании |
| Получение доступных организаций | У пользователя есть доступ к ящику конкретной организации в Диадоке | Должность, право подписания, право зарегистрировать организацию на АСТ «Форум» |
| Проверка КЭП | Пользователь владеет закрытым ключом сертификата | Полномочия представителя, если они не следуют из сертификата или реестра |
| Проверка МЧД | Представитель наделён указанными в доверенности полномочиями | Полномочия за пределами доверенности или после её отзыва |
| Проверка ЕГРЮЛ/ЕГРИП через Контур.Фокус | Реквизиты и руководитель организации по открытым данным | Владение учётной записью или фактическое согласие организации |

## Рекомендуемый сценарий регистрации ЮЛ и ИП

### 1. Выбор способа входа

В модальном окне входа показать единый список способов:

1. **Войти по Сбер ID** — для физического лица.
2. **Войти через Контур.Диадок** — для юридического лица и ИП.

Контур.Фокус не следует называть способом входа: он не является провайдером авторизации пользователя.

### 2. Авторизация в Диадоке

1. Пользователь нажимает **«Войти через Контур.Диадок»**.
2. Backend перенаправляет его на OpenID Provider Диадока по Authorization Code Flow.
3. Пользователь проходит вход и даёт приложению согласие на запрошенные права.
4. После обратного перехода backend обменивает код на `access_token`.
5. Токен хранится только на сервере и применяется для запросов к API Диадока от имени пользователя.

Для этого сценария использовать OpenID Connect — Контур рекомендует его вместо устаревшей схемы авторизации через методы Диадока.

### 3. Подтверждение связи с организацией

1. Backend вызывает метод `GetMyOrganizations` API Диадока с пользовательским токеном.
2. Пользователю показывается список доступных организаций.
3. Пользователь выбирает организацию, от имени которой создаёт аккаунт на АСТ «Форум».
4. Система сохраняет идентификатор организации Диадока, ИНН/КПП, идентификатор пользователя Диадока, дату входа и версию согласия.
5. Для ИП система сравнивает ИНН выбранной организации с данными профиля. Для ЮЛ — ИНН и КПП.

Результат этого этапа: статус **«Доступ к организации в Диадоке подтверждён»**.

### 4. Проверка полномочий первого администратора

Проверку полномочий выполнять отдельно от входа.

#### Если пользователь — руководитель

1. Получить реквизиты организации и сведения о руководителе из ЕГРЮЛ через Контур.Фокус или источник ФНС.
2. Сопоставить ФИО пользователя с данными сертификата КЭП и данными руководителя.
3. Предложить пользователю подписать короткое заявление о регистрации организации на платформе своей КЭП.
4. Проверить сертификат, его срок действия и факт владения закрытым ключом по результату подписи.
5. При совпадении данных присвоить статус **«Полномочия руководителя подтверждены»**.

#### Если пользователь — представитель

1. Авторизовать пользователя через Диадок и получить доступную ему организацию.
2. Запросить МЧД или иной документ, подтверждающий полномочие на регистрацию и администрирование аккаунта организации.
3. Проверить, что МЧД действительна, выдана нужной организацией и содержит требуемое полномочие.
4. Сопоставить ИНН доверителя, ИНН представителя и данные сертификата КЭП.
5. Сохранить номер МЧД, срок действия, основание полномочий и результат проверки в аудите.
6. При необходимости направить заявку на ручную модерацию.

#### Если подтверждения недостаточно

Не открывать критичные действия организации до решения модератора. Разрешить пользователю сохранить черновик и загрузить дополнительные документы.

## Техническая последовательность

```text
Пользователь
  → «Войти через Контур.Диадок»
  → OpenID Connect Диадока
  → access_token на backend
  → GetMyOrganizations
  → выбор организации
  → проверка КЭП и/или МЧД
  → Контур.Фокус: реквизиты и статус
  → решение автоматики или модератора
  → создание аккаунта организации
```

## Данные, которые нужно хранить в аудите

- идентификатор пользователя Диадока;
- идентификатор ящика и организации Диадока;
- ИНН, КПП и ОГРН/ОГРНИП выбранной организации;
- дату и время авторизации;
- результат сопоставления реквизитов;
- отпечаток сертификата КЭП, если использовался;
- номер и срок МЧД, если использовалась;
- результат автоматической проверки и решение модератора;
- дату следующей повторной проверки.

Не хранить закрытый ключ, пароль пользователя или избыточные данные сертификата.

## Статусы в продукте

| Статус | Условие | Доступ |
| --- | --- | --- |
| Черновик регистрации | Организация ещё не выбрана или вход не завершён | Только редактирование заявки |
| Связь с организацией подтверждена | Пользователь получил организацию через Диадок | Ограниченный доступ до проверки полномочий |
| Полномочия проверяются | Подпись, МЧД или документы отправлены на проверку | Без публикаций и сделок |
| Полномочия подтверждены | Руководитель или представитель успешно проверен | Полный доступ администратора организации |
| Требуются документы | Недостаточно данных или есть расхождение | Только редактирование и загрузка документов |
| Отклонено | МЧД недействительна, сертификат не прошёл проверку или модератор отказал | Вход сохраняется, аккаунт организации не активируется |

## Риски и ограничения

- Доступ к ящику Диадока не равен юридическому полномочию действовать от имени организации.
- Контур.Фокус подтверждает сведения об организации, но не волю организации и не владение учётной записью пользователем.
- КЭП подтверждает владение ключом; для представителя необходимо учесть основание полномочий, в том числе МЧД.
- Проверка МЧД и КЭП должна быть согласована с юридической службой до запуска в production.
- Нужно определить, какие действия требуют полного подтверждения: создание организации, публикация лота, подписание документов, изменение реквизитов, добавление сотрудников.

## Изменения в макетах

В форме входа заменить кнопку **«Войти через Контур.Фокус»** на **«Войти через Контур.Диадок»**. После входа показать выбор доступной организации и следующий шаг проверки полномочий.
